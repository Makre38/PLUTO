## 1. sbatchでケース生成だけを実行する

現在の `submit_*` スクリプトは、生成済みケースの計算を投入するためのものです。ケース生成専用のsbatchラッパーは追加していません。会話では、既存のTOML生成コマンドを `sbatch --wrap` で投入する方法を案内しました。

リモートのrepo直下で実行する例です。partitionと制限時間は利用環境に合わせて指定します。

```bash
sbatch \
  --job-name=prepare-cases \
  --partition=YOUR_PARTITION \
  --nodes=1 \
  --ntasks=1 \
  --time=00:10:00 \
  --output='prepare-%j.out' \
  --wrap='bash scripts/prepare_from_toml.sh configs/examples/mach_sweep.toml'
```

- これは生成コマンドだけをジョブ内で実行します。PLUTOのビルド・計算や、それらのジョブ投入は行いません。
- 作業ディレクトリは通常、sbatchを呼んだディレクトリです。別の場所から投入する場合は `--chdir` でrepoの場所を指定できます。
- 計算ノードからrepo・設定ファイル・出力先を参照でき、Juliaと既存生成シェルが使用するコマンドを使える必要があります。Julia等のmoduleロードが必要な環境では、その手順を含むバッチスクリプトを別途使います。
- Gitは任意の版情報記録だけに使われ、Gitや `.git` がないことを理由に生成は停止しません。
- 生成終了後はログのcase一覧・manifestを確認し、既存の単一ケース／sweep投入スクリプトで必要な計算だけを投入します。

これは会話で提示した操作例であり、Codexが実際のリモートSlurm上で投入・検証したものではありません。Slurmのオプションの意味は [sbatch公式マニュアル](https://slurm.schedmd.com/sbatch.html) を参照してください。

ユーザーからの「リモートでもケース生成が通った」という報告自体は、すでに [11月6日の報告・検証状況](report-2026-11-06.md#4-検証状況) に記載済みです。その報告から、生成をどの投入方法で行ったか、リモート計算が完了したか、MPIや物理収束を確認したかまでは判断しません。

## 2. Machアラートを残し、既定で無効にした理由

ユーザーの説明では、MachアラートはCFL条件を誤っていた頃の診断の名残であり、CFL修正後の通常の計算では発動しなくなっています。これはユーザー報告で、今回新たに本番ログを検査した結果ではありません。

速度勾配導入後などに診断を必要とする可能性を考え、機能は削除せず、既定で無効とする方針を合意しました。高Machそのものが必ず数値異常を意味するわけではないため、目的に合う閾値を必要時に設定します。

- `mach_threshold = 0.0` は無効です。正の閾値を明示すると有効になります。
- `mach_every_steps` は、閾値超過が継続する間に何ステップごとに再記録するかを指定します。無効時には再記録間隔は使われません。
- 音速アラートは現状を維持します。閾値・再記録間隔をTOMLで設定でき、閾値0で無効化します。
- sweepでは診断を無効にする場合も、閾値0と記録間隔を含む全共通項目の明示が必要です。

設定値の仕様と実装済みテストは、上記のTOML仕様と [テストレポート](test_reports/toml_setup_julia.md) にあります。

## 3. 実装前ブリーフィングで明確にすること

今回の問題は、Pythonという言語の選択だけでなく、Git必須化やケースの一時生成など、ユーザーが把握していなかった依存・運用上の変更を実装側で追加したことでした。確認回数を増やすより、最初の説明で重要な選択を具体化する方針です。

非自明な実装では、次を提示し、合意済みの事項・提案・未決定の事項を区別します。

| 確認項目 | 説明する内容 |
| --- | --- |
| 範囲・操作 | 何を変更し、ユーザーはどのコマンドをどう使うか |
| 言語・依存 | 使用言語、必須ツール・パッケージ・版条件、任意の情報源 |
| 入出力 | 設定、保存先、追加ファイル、相対パスの基準 |
| 既存との差 | 既定値、上書き、一時領域、途中失敗時に残るもの |
| 検証・完了 | 何を確認したら完了か、結果をどこに保存するか |

合意後に未説明の依存や重要な外部挙動の変更が必要になれば、理由・影響を説明して実装前に確認します。関数の分割など、合意した外部挙動を変えない内部詳細は実装側で判断できます。

repoの `AGENTS.md` は、この方針とJulia優先・他言語使用時の事前確認・読める検証記録を含む英語の指示として作成済みです。存在するPythonスクリプトは新規のPython利用を無条件で承認する根拠にはなりません。既存のignore指定に従い `AGENTS.md` はGit管理外であり、この文書はその指示の代替ではありません。

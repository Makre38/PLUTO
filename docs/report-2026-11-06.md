## 1. 研究目的と現在の物理モデル

最終目標は、流れに垂直な方向へ速度勾配を持つガス中で、固定された重力源に働く力を測定することです。例えば背景流を `v = vx(y) e_x` として、流れ方向の力 `Fx` と勾配方向の力 `Fy` を調べます。

現段階は、一様密度・一様速度のガスを使う基準計算です。PLUTOで流体計算を行い、Juliaで密度場から重力源に働く力を解析します。Ostriker型の解析的な動摩擦との比較を目指していますが、物理的な収束や一致が確立した段階ではありません。2Dは主に実装・診断用で、主な定量的研究対象は3Dです。

現在扱うのは、**吸収を伴わない、重力をsofteningした固定重力源**です。中心sinkは撤廃しました。流体の自己重力や降着モデルを今回追加したわけではありません。

コード単位で `G = 1` とし、主要な長さは次のように区別します。

```text
V_inf = Mach * cs0
r_B   = M_p / cs0^2
r_BHL = M_p / [cs0^2 * (1 + Mach^2)]
A_SOFT = r_B / r_soft
r_soft = r_B / A_SOFT
```

- `r_soft` はPlummerポテンシャル `Phi = -M_p / sqrt(r^2 + r_soft^2)` を正則化する長さです。
- `A_SOFT` が大きいほど `r_soft` は小さくなります。例えば `A_SOFT=4` は `r_soft=r_B/4` です。
- 旧方式の `RSOFT_FRAC` は `r_soft/r_BHL` で、A_SOFTとは基準半径と比の向きが異なります。両方式の同時指定は禁止です。
- 力積分から除外する半径 `r_cut` はsofteningとは別です。既存の一ケース解析は概ね `r_cut=r_BHL` を使い、その妥当性・依存性は未検証です。
- sink半径は過去の吸収モデルの設定であり、これらの半径と同一視しません。

現在の正方向は、固定重力源に対して背景ガスが `+x` に流れる場合の `Fdf=Fx` です。過去の `Fdf=-Fx` で作られた解析出力と混在させないことが必要です。この符号統一と可変softening・動径力診断の初期実装は、本報告対象期間より前に行われた前提作業です。

### 2.1 生の密度摂動プロファイル

`plot_alpha_profile_3d.jl` を追加しました。

```bash
julia plot_alpha_profile_3d.jl RUN_DIR 2.0
```

- 指定した `log Lambda = ln(t*cs0/r_BHL)` に最も近い正時刻のスナップショットを選択します。時間補間はしません。
- 重力源を通るx方向の線、すなわち `(y,z)=(y_p,z_p)` 上の `alpha=rho/rho0-1` を描きます。
- y・z方向はセル中心値から双線形補間し、正確にセル中心に一致するときはその値を使います。範囲外への外挿はしません。
- x方向はセル中心をそのまま使い、横軸は `x-x_p`、縦軸は対数変換しない符号付きalphaです。
- PNGと、座標・rho・alpha・選択時刻・補間情報を含む数値表を出力します。
- 必要な最大4本のrhoのx方向列だけを読み、3D配列全体の読み込みを避けます。
- 対象は3D Cartesianのsingle_file double出力です。別軸、2Dの生alpha断面、アニメーションは初版にはありません。

### 2.2 sink撤廃

ユーザーの確認では、sinkなしでも計算は破綻せず進行します。今後の研究対象を非吸収重力源とするため、sink機能を撤廃しました。これは「softeningが重要でない」と実証したためではありません。

削除したのは、中心領域での密度・圧力・速度の緩和、専用統計・ログ、sinkパラメータ、ケース名やsweep生成でのsink指定です。`INTERNAL_BOUNDARY` を無効化し、3Dのユーザーパラメータを16から13へ整理しました。重力、softening、一様流入、音速・Mach診断、力解析は維持しています。

旧 `SINK_RADIUS`、`SINK_TIMESCALE`、`SINK_TAPER_POWER` と、さらに古い `SINK_RHO_FLOOR`、`SINK_VELOCITY_FACTOR` は、新規生成用の既存3Dシェルスクリプトでは指定があればエラーになります。ゼロや空文字でも同様です。TOML方式ではsinkキーを拒否し、継承されたsink環境変数は使用しません。

過去のrunやスナップショットは書き換えておらず、古いsummaryのsink項目があっても解析できます。過去のsink付きモデルを再実行する場合は、その時点のCソース・definitions・pluto.iniを一式で保持し、新旧のパラメータ番号を混在させないようにします。

### 2.3 CFLとsofteningに関する認識の訂正

ユーザーから次の結果が報告されました。

- sinkなしでも計算は破綻しない。
- テストした条件では、`CFL < 1/dim` の範囲でCFLを変えても計算結果はほとんど変わらなかった。
- 「softeningを変えても影響が小さかった」という記憶はCFL比較と混同したもので、**softening依存性はまだ未検証**。

これらの比較runの個別設定、到達時刻、比較量、誤差許容値は、この会話では提示・独立確認されていません。したがって一般的な安定性保証や物理収束の証拠には拡張しません。

ユーザーがCFL既定値を `0.333` に変更しました。現在はTOMLおよび既存環境変数方式の `CFL` で明示指定できます。TOMLでは `0 < CFL < 1/3` を検証します。従来の環境変数方式では正の有限値を検証しますが、この上限制約は同一ではありません。

## 3. TOML設定：現行仕様

### 3.1 使用方法と担当範囲

```bash
bash scripts/prepare_from_toml.sh configs/examples/single.toml
bash scripts/prepare_from_toml.sh configs/examples/mach_sweep.toml
bash scripts/prepare_from_toml.sh configs/examples/softening_sweep.toml
```

シェルの入口から `scripts/prepare_from_toml.jl` を呼び、Julia標準ライブラリのTOMLで読み込み・検証して、既存の3D生成シェルスクリプトを利用します。現行のTOML経路にPythonは不要です。最初に追加したPythonのTOML実装・テストは削除しました。なお、それ以前からの `tests/test_softening_generation.py` は別の既存テストとして残っています。

TOMLの責務はケース生成までです。コンパイル、計算実行、MPI、Slurmへの投入は既存の別スクリプトで行います。sweepで生成したケースの一つだけを後から投入・再投入できます。生成専用のsbatchラッパーは追加していません。

### 3.2 管理する設定

| テーブル | 設定内容 |
| --- | --- |
| `physics` | Mach、gamma、重力源質量、背景密度・音速 |
| `softening` | `a_soft` または `rsoft_frac` |
| `grid` | BHL半径あたりのセル数、上流・下流・横方向の余裕係数、最小上流長 |
| `time` | `log_lambda_max`、CFL |
| `output` | 出力回数、runの保存先、データ出力サブディレクトリ |
| `limits` | セル数の警告・上限、softening解像度と境界距離の警告基準 |
| `diagnostics` | 音速・Machアラートの閾値と再記録ステップ間隔 |

`schema_version=1` を必須とします。格子数、Bondi/BHL半径、softening半径、終了時刻、出力間隔などは入力条件から計算します。`margin_y` は現行3D生成器のy・z両方向に使われます。

PLUTOの場所、コンパイラ／ビルド設定、MPI並列数・ランチャー、Slurm partition・制限時間・依存ジョブは、TOMLに含めていません。

### 3.3 sweepと省略規則

`sweep.parameter` は `physics.mach` または `softening.a_soft` の一つで、`sweep.values` に値を列挙します。複数軸の組み合わせ展開や、最小・最大・刻み指定は扱いません。

```toml
[sweep]
parameter = "physics.mach"
values = [0.1, 0.3, 0.5, 0.7, 0.9, 1.1]
```

これはsweep部分だけの例で、単独では現行仕様の完全な設定ではありません。

**sweepでは掃引対象以外の全共通設定を明示必須**としています。物理条件だけでなく、出力先、診断の無効指定、記録間隔、セル数制限も記載します。softeningは2方式のどちらか一つを指定し、`a_soft`を掃引するなら固定softening指定は書きません。不足項目はまとめて表示し、ケース・manifest生成前に非ゼロ終了します。共有のsweep例は全共通設定を記載済みです。

単一ケースでは省略と既定値の利用を引き続き認めています。例えばCFLは0.333、gammaは1.6666、softening指定なしなら `rsoft_frac=0.25` です。これは「sweepだけ明示必須」とした現時点の仕様です。

音速アラートの単一ケース既定閾値は `1e-6`、Machアラートは既定で無効（閾値0）です。再記録間隔の既定値は各1ステップです。`mach_every_steps` 等は閾値超過が継続している間の再記録頻度であり、物理量そのものの設定ではありません。

### 3.4 ファイル・パス・失敗時の挙動

- 相対出力先はTOMLのあるディレクトリを基準に解決します。単一ケースで省略した `runs_dir` はそこから `../../runs_3d` です。
- `configs/examples/` を共有例、Git管理外の `configs/local/` を個人の試行設定に使います。
- 設定値はTOMLと明記された既定値から決定します。既存シェル環境の `MACH` や `CFL` が暗黙に上書きすることはありません。
- **指定先に直接、順番にケースを生成します。ケースの一時生成領域と、そこからのコピー処理は廃止しました。**
- 後続ケースで格子計算やセル数上限により失敗しても、成功したケースとmanifestの記録は保持します。
- TOML経由では既存ケースを上書きしません。生成途中の書き込み失敗では不完全なディレクトリが残る可能性があるため、再実行前に状態確認が必要です。
- 各ケースに `setup.original.toml`、`setup.effective.toml`、`run_summary.txt` を保存します。effectiveは既定値・派生情報を含む記録であり、そのまま入力TOMLとして再利用する形式ではありません。
- Gitはケース生成に必須ではありません。取得できるときだけコード版・変更状態を記録します。取得できなければ `metadata_available=false`、`revision="unavailable"`、`dirty="unknown"` と記録して継続します。「変更なし」とは記録しません。
